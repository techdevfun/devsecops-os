# Contributing to devsecops-os

Thank you for your interest in the project. devsecops-os is an
open-source, vendor-neutral DevSecOps operating layer: a reference
architecture + a policy-as-code pack + 10 CI gates + audit-evidence
automation. Every contribution goes through the same verification
standard the project applies to itself: **never claim something that
has not been run for real**.

## Before you start

- Read `README.md` (the architecture, the 10 gates, how to run
  locally) and `docs/` (the reference architecture, the control map).
- Security issues: do NOT open a public issue — see `SECURITY.md`.

## Development environment

The pipeline tools are version-pinned and placed in
`~/workspace/tools` on the project's development machine (see
`gates/local/README.md` for the list + versions): OPA, conftest,
gitleaks, Semgrep, osv-scanner, Trivy, Terraform, Syft, Cosign,
Kyverno CLI. The entire test suite runs **locally, with no cloud
account required**:

```bash
# Test the policy pack (OPA + harness + Kyverno)
~/workspace/tools/opa test policies/rego/
python3 policies/harness/run_checks.py
bash policies/harness/kyverno_check.sh

# Test the evidence tooling (collector + generators)
python3 -m unittest discover -s evidence/tests

# Test the gate adapters
python3 -m unittest discover -s gates/local/tests
```

## Contribution rules

1. **A new/changed policy must have all 4 things**: the Rego file
   (or Kyverno), the corresponding evidence schema in
   `policies/evidence-schemas/`, pass + fail fixtures in
   `policies/fixtures/`, and a documentation entry in
   `policies/docs/`. Missing any one of the four, the PR is not ready.
2. **Every behaviour change must have a test that runs red first,
   green after** (red-first): the new test must fail on the old code
   and pass on the new code. Record the command run + the result in
   the PR description.
3. **Do not loosen a gate to "let it pass"**: do not lower severity,
   do not add unbounded exceptions, do not disable a gate in
   `all-gates.yml` without a decision recorded in `CHANGELOG.md`
   together with the reason.
4. **Evidence must be generated from real data**: sample records in
   documentation/tests must be generated by the project's own tools
   from data in the tree — do not hand-write records that "look real".
5. **Do not commit secrets, private keys or customer data** — not
   even in fixtures. A fixture containing a fake secret must be
   clearly marked as fake (for example with the `FAKENOTREAL`
   suffix) and must live only in the `planted/` variant.
6. Update `CHANGELOG.md` for every user-visible change (policy,
   gate, schema, collector behaviour).

## PR process

1. Fork/branch from `main`, one PR with one purpose.
2. Run all 5 test suites above; paste the results into the PR.
3. A PR into a protected branch needs at least 1 approval from
   someone other than the author (this is also the condition the
   `change_record` policy checks in the change evidence).
4. CI must be green across all 10 gates that apply to the change;
   blocking gates must not be skipped with a label.

## Style

- Documentation: Vietnamese with diacritics for internal operational
  documents, English for READMEs/schemas/technical names; stay
  consistent with the neighbouring file.
- Python code in `evidence/` and `gates/local/adapters/` uses only
  the standard library (except adapters with a declared dependency,
  for example `workflow_input.py` uses PyYAML) — so the tools run on
  any runner with no extra installation step.
- Rego: write in OPA v1 syntax (no `import rego.v1` needed; use
  `if`/`contains` as in the existing policies in `policies/rego/`).
