# provenance — an artefact must have an SBOM + signature + SLSA matching the digest

- **Code**: `devsecops.provenance` · **Mechanism**: OPA/Rego at the deployment
  decision point (data generated by Gate 6); enforced at the target layer by
  Kyverno `verifyImages` (see `../kyverno/verify-image-signatures.yaml`)
  · **Consuming gate**: Gate 6 (SBOM + attestation) · **Evidence**:
  `provenance-attestation` + `sbom`.

**Which control** (reference mapping): SSDF PS.3 (protect all forms of
software, provenance); ISO 27001 A.5.19–A.5.22 (suppliers — here
the organisation's own pipeline in the role of internal supplier) and
A.8.28; SOC 2 CC7.1/CC8.1 at reference level.

**Why**: a matching digest across the artefact, signature and provenance is the only
way to answer "is the running image exactly the image the pipeline
built from that commit" — the core question of supply-chain security
after action/registry takeover incidents.

**How to fix a violation**: build through a pipeline with Syft (SBOM) +
Cosign keyless (signing with OIDC) + slsa-github-generator (provenance) enabled;
do not deploy artefacts built outside the pipeline; if the provenance does not
match the digest, investigate as an incident — do not overwrite by hand.
